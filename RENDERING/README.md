# RENDERING

`ArmyRenderer.cs` creates six MultiMesh batches (two factions × three shapes), allocates exact deployment capacities and packs live slots on death. Dirty entries update reusable CPU buffers. Dense changes upload one buffer per affected batch. Sparse changes update individual slots. `ProjectileRenderer.cs` owns one capped MultiMesh for the projectile pool. Soldier meshes are shared between factions and authored by `FacetedSoldierMeshes.cs` with brighter top faces and directionally darker sides (baked per-vertex grayscale tints). The existing MultiMesh blue/red instance colours multiply those tints; white damage flashes remain visible with darker side facets. Materials remain unshaded, requiring no lights or dynamic shadows; there are still six batches and no per-unit geometry or shading updates. Shadows are disabled. Render sync runs on the main thread and is measured separately from simulation. Whole-batch culling, no interpolation/LOD; no per-soldier nodes. BENCHMARK owns renderer creation/disposal.
